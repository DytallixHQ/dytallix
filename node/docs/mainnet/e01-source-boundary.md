# E01 source boundary

Status: **E01 source-level engineering complete on the maintained source**
(`mainnet/node` in `exocognosis/dytallix`), 26 September 2026. This supersedes
the 25 September record in the launch decision register, which certified
file archives taken from an uncommitted checkout. It grants no G35 or launch
approval: compiled artifacts and loaded providers are T01, the live peer path
is T02, production values are E05 and the release freeze is E06. Mainnet
remains `NO_GO`.

## What changed since the 25 September record

- **Source identity.** The record is now bound to Git: the inventory
  ([e01-crypto-inventory.json](e01-crypto-inventory.json)) pins each routed
  file's SHA-256, and CI fails when a routed file changes without a reviewed
  regeneration (`scripts/e01_inventory.py --check`).
- **Drift.** Seven of the 27 files the old record pinned had changed. Four
  changed by removal only (#240 removed the ML-DSA-87 development branch, the
  no-backend stubs and the legacy Dilithium5 and unsigned paths from
  `runtime-crypto` and `signed_transaction.rs`). Three carry E02 AppArmor
  role changes, not cryptography.
- **Coverage.** The route trace grew from 9 roles and 23 files to 13 roles and
  46 files. Newly recorded: governance v3 verification, the legacy signed
  path's verifier and policy, account address derivation, validator key
  proofs, the Rust callers of root authorization, `pqcp2p/identity.go`, and
  eight fixture and verification tools.

## Source changes in this step (E01.3, E01.4)

1. **Remote signing removed from PQC-only builds.** `privval` now compiles
   only the file signer (`doc.go`, `errors.go`, `file.go`); the signer client,
   server, endpoints, socket dialers and listeners, message wrapping and
   Noise listener carry `!dytallix_pqc_only`. `node` rejects a configured
   remote-signer address. Previously the code was compiled in and reached
   only through stubs that returned errors (old exception 1).
2. **Classical packages cannot compile under the tags.** Every file in the
   fork's `crypto/ed25519`, `crypto/secp256k1`, `crypto/secp256k1eth`,
   `crypto/bls12381` and `lp2p` carries `!dytallix_pqc_only`, so an import from
   a production build fails compilation instead of relying on graph review.
3. **Strict `privval` and `node` tests build and pass** (old exception 2).
   Legacy remote-signer and Ed25519 tests are tagged out; the key round-trip
   test has an ML-DSA-65 variant.
4. **Only ML-DSA-65 is representable** in the Rust generic verifier
   (`PQCAlgorithm`) and the signature policy (`SignatureAlgorithm`). The
   Dilithium3/5, Falcon, SPHINCS+ and ML-DSA-87 labels, which parsed and were
   then rejected, no longer parse. The legacy mempool's policy, which
   allowlisted those algorithms and labelled every transaction Dilithium5
   while verifying ML-DSA-65, now matches the verifier.
5. **CI enforces the production Go build.** The Go job previously built and
   tested only the default development tags. It now vets, tests and builds the
   engine and bridge with `dytallix_pqc_only,dytallix_pqc_ipc`, and runs
   `scripts/check_consensus_go_graph.py`, which fails on a prohibited package
   in a selected graph, a classical fork package that becomes buildable, or
   remote-signer sources in `privval`.
